# Contributing

Use a focused branch and keep changes within the approved product boundaries.
Before requesting review:

```powershell
npm ci
npm run verify
```

Describe the user objective, acceptance criteria, architecture impact, edge
cases, error handling, security, performance, accessibility, and test strategy.
Signal or model changes must also update the signal specification, model
governance evidence, project memory, and relevant decision or technical-debt
records.

Never commit secrets, licensed raw data, production model artifacts, device
tokens, or personal data.
